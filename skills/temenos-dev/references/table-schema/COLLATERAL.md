| 4 | `COLL.APPLICATION.ID` | `Collateral_ApplicationId` | TField | Conditional | The contract or account id by which the collateral object is represented. This field is used to link the collateral to a deposit or credit balance recorded elsewhere in the system. Valid input is any contract/account number as follows: account number; item-id to account file bill contract number with OPERATION as COLLATERAL fiduciary deposit (order) number letter of credit transaction number (loans &amp;) deposits contract number, miscellaneous deal number, money market contract number, securities portfolio number, sub-asset group within a portfolio, security id within a sub-asset group within a portfolio, property asset reference; item-id to ASSET.REG.PROPERTY file, mortgage asset reference; item-id to CO.REG.PROPERTY file. If a deposit contract, contingent asset or account is referenced, the system will calculate its current value and place this in NOMINAL.VALUE and/or EXECUTION.VALUE of the COLLATERAL record according to the definition of fed &amp; fed/margin values. If a portfolio number is entered, a similar action is taken, except that the system will first observe the definition of asset &amp; sub-asset types belonging to the COLLATERAL.TYPE. The rules for defining assets of a portfolio and for the system's calculation of their value is described below. If the APPLICATION.ID in this field is entered in the format: customer number; '-'; portfolio number; '.'; sub-asset type; '.'; asset type;'*'; security number. The actual collateral value will be the margin value of the individual security. Validation ensures the security number is valid and that it is part of the portfolio. The security number can be entered as either a full security number, a mnemonic or as short form input. If the APPLICATION.ID in this field is entered in the format: customer number; '-'; portfolio number; '.'; sub-asset type; '.'; asset type, then it forms the key to a record on the SC POS ASSET file. This refers to a particular group of assets within a portfolio (as defined by asset &amp; sub-asset type). In this case, the value of the collateral is calculated by taking the current value of the assets which belong to this group but not including any particular items which are defined elsewhere as collateral (i.e. individual accounts, deposits etc). If the APPLICATION ID is entered in the format: customer number; '- '; portfolio number, then it refers to a record on the SEC.ACC.MASTER file and defines either the whole portfolio or a part of it according to the COLLATERAL.TYPE. The calculation of the associated value is described below. If a SEC.ACC.MASTER id is entered, the system will check the COLLATERAL.TYPE record indicated by the content of field 1. If this record has a list or a range of asset &amp; sub-asset types associated with it, the system will assign the value of only those assets of the portfolio which correspond to one of the defined types or fall within one of the defined ranges. The value of any individual accounts or contracts which are defined separately as collateral items will not be taken into account. If an individual SC POS ASSET record belonging to the portfolio is separately defined as a collateral item, its value, too, will be disregarded. Finally, if a complete portfolio is referenced, by SEC.ACC.MASTER id under a COLLATERAL.TYPE for which no asset groupings have been defined, the full value of the portfolio is calculated. However, the same rules apply to individually defined items at a lower level of detail. In other words, values of individual assets will be ignored if they are separately defined (either by direct reference, by SC.POS.ASSET id or by inclusion in an asset group defined at the level of COLLATERAL.TYPE). In each case, the reference given should belong to the customer mentioned in the item-id to the collateral record. If this is not the case, an override condition must be accepted. For external assets, the application Id can be of any format. For such assets, the application will be determined from COLLATERAL.TYPE. The above mentioned override will not be raised for External type assets since the customer Id cannot be determined for such type of assets. The collateral type determines whether input to this field is mandatory, optional or not allowed. Validation Rules: Up to 34 alphanumeric characters; exact format determined by the application to which the reference belongs. (Optional input, depending on collateral type) Input is not permitted if the value of APPLICATION.INPUT on the COLLATERAL.TYPE file is 'N'. The reference must belong to one of the permitted applications defined under APPLICATION on the COLLATERAL.TYPE file. MD.DEALS where the client of the contract and the COLLATERAL id are the same must be Asset types Allows both contingent and non-contingent accounts. Account must be contingent when ALLOWED.ACT.BAL field of COLLATERAL.TYPE is MINUS or BOTH Application Id with '!' character is not allowed to be linked for external assets and an error will be raised for such cases. This is to avoid conflict with the COLLATERAL.EXCLUSION Id maintained in the field ExclusionId in collateral. Id length should be greater than 12 with the prefix 'PTY' or 'MTG' for property and mortgage assets respectively. This is required to avoid conflict with the mnemonic. |
