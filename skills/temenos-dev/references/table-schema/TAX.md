| 3 | `EB.TAX.RATE` | `Tax_Rate` | TField |  | Specifies the Rate used to calculate the amount of Tax applicable. Special care should be taken by the user when the Interest Rates quoted to the Customer are "Net of Taxes". If this is the way you quote credit interest rate to your customers, the tax rate entered into this field must then be "GROSSED UP" to allow the System to calculate the correct Tax amount and the NET amount of interest. Example: Let us suppose that the Tax Rate applicable on credit interest is equal to 20%. If a customer is offered 10% for a month deposit, the net Interest Rate for the Customer will be 8%. If this is the Rate quoted (Net rate i.e. 8%), a Tax ID must then be defined in this table with a Tax Rate of "25%" to enable the correct calculation of the Tax amount. Note: The formula to calulate the grossed up Rate is: ( i ) 100 i.e. (100 - i) ( 20 ) 100 =25% (100 - 20) Validation Rules: 1-10 type R (Standard Rate Format upto 6 integer and 9 decimal) numeric characters. Not more than 6 integers may be entered. Not more than 9 decimals may be entered. Can not be input if banded taxes are specified. |

| 29 | `EB.TAX.UNIQUE.SUFFIX` | `Tax_UniqueSuffix` | TField | No | Specifies if the tax account number to be credited is the same tax account for all postings, or a different account for each transaction. The tax account number is constructed in the format CCY ccccc nnnn where: CCY is the currency of the transaction, or the local currency (depending on the TAX.IN.LOCAL field) Ccccc is the 5 digit CATEGORY code. Nnnn is a 4 digit suffix, either fixed as 0001 if this field is not set to Y, or a random number formatted with leading zeroes if this field is set to Y. In high volume environments where tax is taken on many transactions it may be desirable to set this field to Y for performance reasons. When this field is not set each transaction involving tax will be posted to the same account (the suffix will be 0001), as a result locking situations may be encountered whilst the other transactions complete. Setting this field will allocate a different tax account per transaction by using a different suffix generated as random number thereby avoiding the locking situation. The random number is by default between 1 and 20, but can be increased by setting the field MAX.TAX.SUFFIX in ACCOUNT.PARAMETER. Validation Rules: Optional input Possible value Y Note - Currently, in high volume environments where tax is taken on many transactions will not result in locking situations as HVT concepts facilitates handling of high volume of accounts. Suggest using the same over unique suffix feature. |
