# SEPA / TPH Knowledge Base

Source-grounded reference for SEPA payment processing in Temenos Transact and
Temenos Payment Hub, built by mining this repository's actual product artifacts
(2,053 JARs, 162,842 field definitions, a 130k-chunk PDF vector index) plus
client-supplied documents.

**Read [`provenance.md`](provenance.md) first.** It defines the confidence tags
(`[JAR]`, `[SCHEMA]`, `[PDF]`, `[CLIENT]`, `[PUBLIC]`, `[GAP]`) that every claim
in these files carries, and records exactly what was and was not scanned.

python pipeline/sepa_extract.py  --cache cache --db temenos_knowledge.db --out knowledge/sepa
python pipeline/sepa_javap.py    --jars jar --cache cache --out knowledge/sepa --raw work/javap

## Verifying a field before writing code

Never use a T24 field name that has not been checked:

```bash
python pipeline/validate_fields.py --app PP.CLEARING --fields "PP.CG.SchemeCompliance,PP.CG.BulkingCriteriaAPI"
```

Exit 0 = all verified. Exit 1 = at least one missing, named in the output.

## The four things most likely to be got wrong

1. **EP and TPH are different products.** `SEPA.OUTWARD`/`SEPA.INWARD` is the EP
   module (jBC only, no Java hooks). `POR.TRANSACTION`/`PP.CLEARING` is TPH.
   Establish which one the bank runs before answering anything.
   → [`architecture.md`](architecture.md)
2. **Most of the "per-message" API fields live on `PP.CLEARING`, not
   `PP.CLEARING.SETTING`.** Schema folder, bulking criteria, outward format API and
   ten others are one-per-clearing. → [`config-reference.md`](config-reference.md)
3. **The mapping frameworks are jBC components, not Java classes**, and SEPA STEP2
   implementations ship out of the box (`STEP2determineBulkingCriteria`,
   `validateEBQAforEPC`). Configure before customising.
   → [`mapping-frameworks.md`](mapping-frameworks.md)
4. **Two different hook mechanisms coexist.** Java: subclass a hook class, register
   an `EB.API` METHOD record, point a configuration field at it. jBC: write a
   `SUBROUTINE`, register it in `PP.COMPONENT.API.HOOK` or `PP.STATUS.ACTION`.
   → [`config-hook-map.md`](config-hook-map.md) and
   [`routines/component-api-hooks.md`](routines/component-api-hooks.md)

## Release caveat

The release of the JAR set in `jar/` is not recorded in any artifact. The one
compiler version seen anywhere is **R23_SP12.0**, from a client routine header,
which pins that *routine* — not this JAR set. Confirm the target environment's
release before acting on any configuration or customisation guidance here. `[GAP]`
